# dorang

> *도랑* — 물길 옆에서 흐름을 나누고, 담아 두고, 다시 합치는 작은 물길.

**dorang**은 Go로 작성된 고성능 LLM 게이트웨이다. 애플리케이션과 모델 프로바이더 사이에
자리하며, **노트북에서든 대규모 클러스터에서든 동일하게 동작하도록** 설계되었다 —
단일 바이너리, 필수 의존성 없음.

## 왜 만드는가

대부분의 게이트웨이는 *기능이 많은 것*과 *빠른 것* 중 하나를 고르게 만든다.
dorang은 그 교환을 거부한다. 아래 모든 기능은 요청 핫패스가 무할당(allocation-free)으로
남고, 프로토콜을 늘려도 비용이 선형이 아니라 **상수**로 유지되도록 설계되었다.

### 실제 구독 플랜 구조를 그대로 표현하는 용량 모델

현실의 프로바이더 플랜은 동시성 숫자가 하나가 아니다. 어떤 계정은 **모델과 무관하게**
계정당 3개까지 처리하고, 다른 프로바이더의 코딩 플랜은 **모델별로** 7개를 허용해
모델 두 개면 동시 14개가 된다. dorang은 이것을 직접 표현한다.

```yaml
capacity:
  credential_groups:
    account-a: { max_concurrency: 3 }        # 계정당, 모델 무관
    account-b: { max_concurrency: 3 }
  models:
    - { provider: coding-plan, model: model-x, max_concurrency: 7 }   # (키, 모델)당
    - { provider: coding-plan, model: model-y, max_concurrency: 7 }
```

route · provider group · model · credential group · key 다섯 축을 **전량 또는 전무(all-or-nothing)로
원자적으로** 예약한다. 한 슬롯을 잡은 채로 다른 슬롯을 기다리는 상태 자체가 존재하지 않으므로
**데드락이 구조적으로 불가능**하다.

### 실제로 멈추는 쿼터와 예산

- 토큰 · 요청 수 · 비용에 대한 **5시간 / 일 / 주 / 월** 롤링 윈도우.
- 프로바이더가 잔량 조회 엔드포인트를 제공하면 그것을 폴링한다. 게이트웨이를 거치지 않은
  사용분까지 포함된 **진짜 잔량**을 본다.
- 소진되면 해당 크리덴셜이 물러나고 트래픽이 자동으로 다음 키로 넘어간다.
- 예산은 **쓰기 전에 선점**하므로 동시 요청이 상한을 뚫지 못한다.

### 순서를 헷갈릴 수 없는 접두사 인지 라우팅

KV 캐시가 남아 있는 백엔드로 보내려면 대화 접두사가 **순서까지** 일치하는지 알아야 한다.
dorang은 해시를 체인으로 엮는다.

```
h₀ = H(group)                        hᵢ = H(hᵢ₋₁ ‖ len(cᵢ) ‖ cᵢ)
```

깊이 *i*에서 일치한다는 것은 `c₁..cᵢ`가 **바이트 단위로, 그 순서 그대로** 같다는 증명이다.
순서 교환·삽입·삭제는 모두 다른 값을 만든다.

### 끌 필요가 없는 계측

키별 사용량, 비용, 지연, TTFT, 토큰 수, 폴백 경로를 모든 요청에 대해 기록한다.
계측은 CPU별 링버퍼를 통해 핫패스 밖에서 돌며, 켰을 때의 비용이 5% 미만이 되는 것이 설계 목표다.

### 전체 프로토콜 표면

OpenAI chat/completions/embeddings/responses/audio/images/moderations, Anthropic messages,
rerank, batch, files — 여기에 **범용 패스스루 엔진**을 더해 프로바이더 고유 경로는
어댑터를 새로 짜는 대신 **설정으로 열린다**.

## 확장 범위

| | 노트북 | 소규모 팀 | 엔터프라이즈 |
|---|---|---|---|
| 저장소 | SQLite (내장) | PostgreSQL | PostgreSQL + 파티션 |
| 조정(coordination) | 없음 | 없음 | Redis 또는 PostgreSQL 리스 |
| 노드 | 1 | 1–2 | N, 리더 선출 기반 유지보수 |
| 계측 | 인프로세스, 샘플링 | 전체 원장 | 원장 + 롤업 + 보존정책 |
| 의존성 | **없음** | 1 | 2 |

같은 바이너리와 같은 설정 파일이 전 구간에서 동작한다. 배포 모델을 바꾸는 것이 아니라
**설정을 바꿔서** 확장한다.
