Models & deployments

Every model group, the deployments behind it, and the health of the credentials those deployments draw on. Model names are opaque strings and are never split on any character (DESIGN §2.1), so what is shown is what a client must ask for, byte for byte.

{{if .Compiled}} These rows are the routing table this process compiled, from models: and aliases: in its configuration — the same table GET /v1/models is served from and the same deployment ids the ledger records. They are changed by editing the configuration and reloading it (SIGHUP, or POST /admin/config/reload); /model/* answers 501 here, because a row written to the deployments table would route no traffic differently and a write that changes nothing is worse than a refusal that says so. {{else}} These rows come from the deployment registry, which /model/* also edits. {{end}}
