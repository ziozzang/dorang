## 이미 있던 방어와 해당 없는 기능

- 일반 HTTP 수신 헤더는 net/http의 기본 1MiB 상한, 헤더 읽기 기본 30초, 전체 요청 읽기 2분으로 제한됩니다. 이번 Go 갱신은 HTTP/2·MIME·쿠키·URL·인증서 처리 결함도 제거합니다. HTTP 응답 헤더는 Transport의 기본 상한을 사용하고 WebSocket의 별도 경로만 새 64KiB 상한을 적용했습니다.
- 추론 응답 32MiB, 오류 응답 1MiB, 상태 조사·OAuth 응답 1MiB, 설치 확인 응답 2MiB, SSE 이벤트별 상한과 Bedrock 이진 이벤트 16MiB가 이미 있었습니다. 스트리밍은 전체를 메모리에 쌓지 않습니다. 크기는 헤더 선언만 믿지 않고 실제 읽기에 적용됩니다. 시간은 요청·제공자별 context 및 상태 조사 기본 10초, 그림자 요청 기본 60초로 제한됩니다. 변경된 기본 클라이언트에는 자동 압축 해제가 없습니다.
- 묶음 파일 업로드는 기본 200MiB, JSONL 한 행 16MiB, 최대 5만 행입니다. DiskBlobs/MemBlobs 자체의 복사 함수는 업로드의 제한된 reader를 받습니다. 결과 파일의 디스크·전체 저장량 한도는 이 점검의 문서 파싱 상한과 별개인 운영 용량 정책입니다.
- Go 정규식은 되돌아가며 재시도하지 않는 RE2 계열이며 식은 운영자 설정에서만 컴파일됩니다. Lua 패턴은 기존 명령 수·재귀 깊이 10000·context 시간 검사, 플러그인 실행의 제한을 유지했습니다. 패턴에 원격 입력이 들어와도 별도 무제한 역추적 경로를 추가하지 않았습니다.
- 저장소의 운영 코드에는 zip/tar 압축 해제, Brotli/zlib/zstd 해제, TOML 파서, 직접 HTTP XML 파서가 없습니다. 따라서 zip slip, 압축 항목의 symlink/SUID 복원 기능도 없습니다. 저장 파일의 이름은 내부 식별자이고 업로드 파일 이름을 경로로 쓰지 않습니다.
- XML은 pgx SQL 드라이버의 일반 자료형 처리에서 간접 호출 가능하다고 검사기에 표시됐습니다. 제품 SQL 스키마·HTTP API에는 XML 자료형 입력이 없습니다. 악성 DB 서버가 다른 자료형을 보내는 경우는 신뢰 경계가 달라지는 조건부 경로이며, Go XML 재귀 결함은 도구 버전 갱신으로 수정됐습니다.
- 브라우저의 JSON.parse는 같은 서버가 만든 관리 화면 측정 자료와 그 안의 문자열만 읽습니다. 그 수치는 서버의 고정 자료 구조에서 생성되며 일반 API의 문서 해석 진입점이 아닙니다. 개발용 testing/의 가짜 서버·시험용 Python 도구는 제품 실행 파일에 포함되지 않습니다.
- 파일 I/O·파일 잠금은 운영자가 관리하는 로컬 저장소를 신뢰합니다. 이 패치는 운영자가 선택한 설정 파일의 심볼릭 링크 자체를 금지하지 않으며, 원격 업로드를 읽는 blob 저장소의 루트 탈출을 별도로 막습니다. 사용자가 주입하는 http.Client는 호출자 소유이며 기본 Transport의 변경이 그 클라이언트를 재설정하지 않습니다.
